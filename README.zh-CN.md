# PVF-Agent-Workbench

这是一个给桌面 AI Agent 使用的 DNF PVF 工作台。它已经带好运行环境、PVF 工具、知识和安全规则，复制到新的 64 位 Windows 电脑后也能直接使用。

## 第一次使用

1. 在工作台根目录运行 `.\workbench.bat check`。
2. 用 Agent 打开整个工作台目录。
3. 对 Agent 说：

```text
请先读取 AGENTS.md，并按工作台规则帮助我处理 PVF。
```

4. 提供目标 `Script.pvf`、想修改的内容、是否允许生成输出 PVF，以及能否进游戏测试。

不会代码也没关系。Agent 会自己查知识路由和相关文件；新手只需要把目标说清楚，并先从只读分析开始。

## 工作方式

- 普通任务统一使用 `workbench.bat`。
- 默认只读，不覆盖源 PVF，也不默认修改客户端资源。
- 数字 ID 会先通过正确的 `.lst` 登记表确认。
- 已知职业与技能 ID 时，工作台会一次闭合角色分支和职业技能登记表，不需要猜技能目录。
- 已知 NUT/API 名称时，内置声明查询与目标脚本观察各用一条命令；依赖预览返回的 JSON 已是完整报告，不要求 Agent 再造摘要。
- 真正写出前会先预演；普通改动只检查，中文改动会用临时文件验证并立即清理。确认后生成独立 PVF，并自动备份和复查；同一个源版本的备份核对无误后会复用，不会每次重复复制。
- 多轮迭代时，下一轮变更集可以显式引用上一轮成功的生成记录。工作台会从上一轮输出继续生成，并在部署前确认客户端正处于本轮输入版本，避免“只部署本轮增量”把已经验证的历史改动退回去。
- 本机 profile 默认保存在工作台目录外的用户状态目录；替换或刷新同一路径的工作台不会删除它。旧版目录内 profile 在首次使用 profile 命令时会安全复制过去，旧文件保留不动。
- 中文搜索、`.str` 和 StringLink 编码检查由工作台自动处理，不需要新手增加配置。
- 查任务、副本、装备、道具或 NPC 的中文名称时，工作台会对完整名称字段做字面包含搜索，并按已知类别缩小目录；名称有前后缀、换行或全角/半角括号等常见差异也可直接命中，不会先把名称当脚本符号全包搜索或反复尝试简繁写法。已知类别的命中会同时附带登记 ID，不需要 Agent 再逐条反查；多个名称、同表 ID 或尚未确认的路径可批量处理。宽泛结果过多时会提示优先使用用户已经给出的更具体词。
- 需要实机测试时，可在单独确认后把已复查的输出 PVF 安装到 profile 指定的测试客户端，并支持恢复部署前版本；不会顺便修改 NPK、IMG 或其他客户端资源。
- 普通检查默认只显示摘要，详细报告自动落盘；索引建立后会复用 SHA 绑定缓存。

## 已内置

- Node.js、首选 native PVF 后端和无需 npm/构建的 TypeScript 只读备用后端；
- PVF 字段知识、NUT 接口、标签说明和常用任务路径；
- 商店、物品、技能、任务、掉落、副本、APC、内容提取和依赖分析等工作流；
- 项目级 `dnf-pvf-xpilot` Agent Skill。

不需要外部 `pvf_bridge` MCP、TypeSquirrel、npm 或已下架的 VSCode 插件。如果 native 后端缺少 VC++ 运行库，读取功能仍可使用，但所有 PVF 写入都会被阻止；`workbench.bat check` 会给出修复入口。

普通脚本里的完整中文名称或描述现在支持单行、多行和受控批量修改。同一句完整文字重复出现时，Agent 可以连同目标前后的原文一起定位；如果多个同构部位连相邻内容也相同，还可以把每条改动限定在原始读回中的某个精确块内，只改目标部位。范围数量、边界、内容和位置都会随预演及正式生成一起核对，任何缺失、越界、重叠或变化都会停止。批量时 Agent 必须先声明范围内的准确数量；参数与中文同时变化时会拆开描述，但工作台会把它们作为同一个最终文件检查。同一文件的多条文字会合并处理，不再逐条重复重建。简体和繁体都会先用临时文件验证，再由另一套解析器精确复查。`.str`、StringLink 引用文字、只改半段中文、按出现序号或部位简称猜位置、数量不明确的批量和无法保存的字符仍会被阻止。

普通读取是方便查看的显示结果，可能把繁体转成简体，不能直接复制为修改原文。准备文字修改时，Agent 必须对同一路径重新读取原始 token；如果照抄显示文字导致零命中，工作台会指出应使用的原始读取编码并安全停止，不会自动试遍繁简写法。

普通配置脚本中的完整数字或英文参数修改也按实际 token 安全性处理。`.wdm`、`.twn`、`.rgn`、`.mm`、`.cre`、`.npc` 和 `.msn` 已完成往返验证，不会只因为扩展名不同就被拒绝。新增 `.co`、`.lst`、`.nut`、`.sqr`、`.str`、`.wdm` 现在有明确的受控证据路线：必须提交 `writeProof`，通过格式/登记冲突、脚本结构检查、临时写出或编码往返和独立读回；普通既有 `.co/.lst/.nut/.sqr/.str` 修改仍保持保护。新增世界地图还要同时闭合 registry、UI、dungeon、town/region 入口，静态通过不代替客户端或实机验证。

需要删除一个同时含中文说明和参数的完整选项块时，可以按变更数组顺序写成“清空完整文字 → 删除文字残留块 → 删除参数块”。跨部位正文相同时，每一步共用目标块的精确范围；工作台仍会把同一文件的中文集中为一次字符串表处理，并对最终结果做独立精确复查，其他部位保持不变。任一中间匹配或最终复查不一致都会停止。

生成测试 PVF 后，可以让 Agent“部署到某个测试客户端”。Agent 会先说明目标和备份位置，等你关闭客户端并确认后才安装；测试结束也可以让它恢复。详细流程见 [docs/CLIENT-PVF-DEPLOYMENT.zh-CN.md](docs/CLIENT-PVF-DEPLOYMENT.zh-CN.md)。

详细规则由 Agent 按需读取 [AGENTS.md](AGENTS.md) 和 `knowledge-pack/`。复制到新电脑前可查看 [docs/CLEAN-COPY.zh-CN.md](docs/CLEAN-COPY.zh-CN.md)。
