目标 PVF 和“叹息之塔”这个具体副本名已明确，第一条 shell 命令就是 `workbench.bat pvf-read search --pvf <Script.pvf> --keyword "叹息之塔" --search-path dungeon --limit 20`。即使请求另外提到地图号、层号或一个推测 ID，也必须先使用 SearchName，不能先运行 resolve-lst、resolve-path、list-files 或 search-script；只有用户明确把数字 ID/登记路径作为选择器时才允许直接解析。即使后面还要写 PVF 或记录耗时，也不先运行 `check`；这一条保持裸命令，不加秒表、分号或输出拼接，耗时使用宿主工具返回值。它是默认 SearchName 名称搜索，会自动做安全的字面包含匹配；名称有前后缀、跨行 token 或全角/半角常见标点差异时也能查，不要自己拼正则。未显式指定编码时工作台会自动检查 Cn/Tw，无需手工切换。这个搜索选择只用于定位，不能当作写入编码。

同一任务有多个具体名称时，只运行一次 `workbench.bat pvf-read search-batch --pvf <Script.pvf> --name "叹息之塔" --search-path dungeon --name "<宠物名称>" --search-path creature --limit 20`，让整批只打开一次 PVF 会话。工作台会在同一会话中分别通过 `dungeon/dungeon.lst` 和 `creature/creature.lst` 自动反查，命中项直接带 `registryIdentity` 登记 ID；当 `allReturnedPathsConfirmed=true` 时只批量读回返回路径，不再逐项 `resolve-path`，也不搜索路径、目录或文件名片段做第二次确认。不先运行 search-script，不查 help、不猜英文文件名，也不分别重试 Cn/Tw、简体、繁体或标点变体。若零命中，它也不证明实体不存在；先区分任务分组名和具体实体名，只把同领域查询缩短一次到具体名称，再沿 registry 或依赖证据继续。
这是自然语言实体搜索场景，名称选择器必须优先于任何推测的数字或路径。
