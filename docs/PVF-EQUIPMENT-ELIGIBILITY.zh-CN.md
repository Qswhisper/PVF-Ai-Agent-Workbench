# 装备类型与适用限制的只读取证

该命令以当前 `equipment/equipment.lst` 为全集，逐条检查登记装备的原始字段，并从当前角色／技能登记重新核验精确职业 token。用途是发现装备适用关系中的证据缺口，不分配气息池，也不证明实际可穿戴。

```bat
workbench.bat pvf-read equipment-eligibility-audit --pvf "D:\TaskInput\Script.pvf" --out "D:\TaskEvidence\equipment-run"
```

首次定位仍遵守 AGENTS.md；命令不替代任务要求的首次／最终 fingerprint。读取前后完整源哈希、大小及修改时间必须保持一致。输入和客户端均不写入。

## 覆盖和输出

先在同一只读会话中重建当前角色／技能登记身份，然后完整读取装备登记表。每条记录都输出，包括别名登记、未知类型、读取失败和无法解释的字段；不按 ID 段、目录或历史清单筛选。

输出必须是工作台及输入目录之外的新目录，已有目录不覆盖。目录内包含：

- `EQUIPMENT.ndjson`：第一行是源身份及登记表／字符串表哈希，随后每个登记 ID 恰好一行。每行保留路径、登记行偏移、完整文件原始 SHA256、字段证据及问题。
- `AUDIT.json`：源前后身份、登记及处理计数、类型标签分布、职业 token 解析结果、问题分类和明细文件完整哈希。每类最多三个样本仅用于定位；覆盖依据是完整逐行输出，不能将样本数量当作覆盖量。

采用逐行输出，避免把全部装备正文长期放在内存。完成后重新读取整个明细文件，核对哈希、字节数及写出记录数，再保存并读回报告。最多 200,000 条登记，单条输出 4 MiB、总输出 1 GiB；脚本／字符串表读取上限沿用身份工具。超限、源漂移或输出异常停止，不产生成功报告。中途失败可能留下未完成的明细文件；缺少最终 `AUDIT.json` 时不能作为完整取证使用。

## 字段证据

只抽取 `[equipment type]`、`[sub type]`、`[usable job]`、`[required skill]`、`[required job skill]`、`[character item check]`、`[minimum level]`、`[grade]`、`[rarity]`。其他字段不作语义解释；不读取客户端 NPK、IMG 或 UI 文件。

使用原始 type-5 标签定位，保留所有出现位置，说明文字中的同名文本不产生字段。为控制体积，`fields` 每项为：

```text
[标签, 起始字节, 结束字节（不含）, 下一标签, 是否紧接对应闭合标签, 值列表]
值列表每项 = [原始 token 类型, 原始 UInt32 位模式, ASCII 字符串或 null]
```

整数按有符号 32 位解释；小数按相同四字节的 float32 位模式解释。字符串索引由本轮字符串表完整哈希绑定；非 ASCII 不猜读或纠错。完整文件哈希绑定未选字段。缺失、空值、重复和解析失败分别保留，不能统一填零。可选字段缺失不自动表示数据损坏。

类型分组只使用唯一、可解释的 `[equipment type]` 首个字符串值；尾随整数完整保存，不解释为槽位编号。`[sub type]` 独立记录，不与类型值或目录合并成武器类别答案。缺失子类型仍是缺失，不自动填默认值。

## 职业与技能限制

- `[usable job]` 必须唯一、完整闭合且为非空字符串 token 列表；拼写、空格和大小写按原文与当前 `.chr [job]` 精确匹配，不用目录名或动画职业代替。
- `[all]` 只保留为原文字面标记，不展开成所有职业／转职可用；缺少职业字段也不是全职业可用。
- `[required job skill]` 仅在完整的“职业字符串、整数技能 ID”成对列表中解析，每项回到自己的职业技能登记表，不跨职业补同号目标。
- 未带职业的 `[required skill]` 保持待解释，不能自动从适用职业列表任选一项。人工可以对原文列出的各职业分别核验同号技能，但这些结果仍是分开的候选解释，不证明运行时采用哪条限制。
- `[character item check]` 保留为未解释字段。不能据其现有条目继承历史气息池、分区数量或参数答案。

本工具不解释全部嵌套结构，`rootScopeConfirmed` 始终为 false。唯一字段也不自动证明根级位置和实际生效上下文；重复字段需单独核查，不能用最后一项覆盖。

## 结果边界

`observationComplete` 只表示当前登记范围的字段观察完成。非常规扩展名仍按登记原路径只读取得字节；具有完整可解析结构时保留字段，同时记录后缀尚未审阅，不擅自改名或认定运行时加载成功。无法读取／解析才计入读取解析失败。`ok` 还要求没有待解释或读取问题；失败报告仍保留完整已处理明细。

“待解释”包括本工具尚未解释的正常限制字段，不等于游戏错误数量。即使 `ok=true`，`semanticContractReady` 和 `authorizesPvfGeneration` 也始终是 false。

类型 token、物理穿戴槽位、职业技能门槛、转职可玩范围、气息选项分区及运行效果是不同证据层。必须分别闭合后才可形成设计方案。该检查尚未接入 `pvf-change` 的气息语义门禁；不授权修改、修复或安装 PVF。

新一轮不得读取或复用任何旧职业、旧技能、旧参数或旧池资料作为答案。当前装备限制只作为重新取证材料，不作为旧池复用理由。
