# 公平决斗 APC 等级与专属装备标准化流程

状态：需验证

## 目标

把来源不同、等级和装备口径不一的 APC 收敛到可复用的公平决斗基线，同时保留职业战斗逻辑，并让玩家装备与 APC 装备能够独立调平。

本流程适合现有副本逐个收敛，也适合以后制作新公平决斗路线时建立 APC 模板。它不是全 APC 批量改写授权。

## 阶段一：闭合目标

1. 从 dungeon registry 进入 `.dgn`，再通过 map registry 读取目标 `.map` 的 `[ai character]`。
2. 用 `aicharacter/aicharacter.lst` 解析 APC ID 和 `.aic` 路径。
3. 闭合 `.aic -> .ai -> .key -> 职业 skill registry -> skill/appendage -> equipment/quick item`。
4. 若本轮只研究等级与装备，AI 链仍需确认对象无误，但不顺手改 AI。

## 阶段二：建立原始装备账

按 `[equipment]` 的三列组读取每个装备值，并分别记录：

- registry ID 与实际 `.equ` 路径；
- 部位、最低等级和职业限制；
- 物理/魔法攻击、防御、独立攻击、三速、HP/MP等纯数值；
- `[skill levelup]`、`[skill data up]`、`[all skill item]`；
- `[if]`、`[then]`、appendage、状态、召唤、霸体或复活类效果；
- 魔法石、辅助装备、称号和时装；
- registry 无法解析的值。

无法解析值只能标记为 unresolved。槽位相邻关系可以作为线索，但必须用其他已解析 APC 对照后才能提出推断，不能据此删除或改写。

## 阶段三：设计 APC 专属装备池

1. 玩家公平装备只作为数值和字段模板。
2. APC 使用新的 equipment ID 和独立 `.equ` 文件，避免两套平衡相互牵连。
3. 如果受控写入器只支持替换现有文件，可以选择目标 PVF 内已存在但未登记的同类 `.equ` 作为载体；必须同时证明载体路径未登记、新 ID 空闲、源模板 ID 可解析。
4. 复制完整套装时，主件内 `[set item]` 必须改为新的 APC 成员 ID；只复制文件而不改成员列表会使两套装备互相引用或套装失效。
5. 首轮优先保留未解析值、辅助装备或称号线索、魔法石和时装；它们可以在后续独立专题中继续审计。
6. 原武器或防具若只有攻防、速度和普通技能等级加成，可以在明确设计授权后由标准装备和 AIC 数值承担；若包含触发、appendage、技能运行时修改或职业机制，先记录补偿方案，不直接舍弃。

## 阶段四：单体实验

第一轮只选择一个可快速到达的 APC：

1. 把 APC 等级改为目标公平等级。
2. 替换武器、五件防具和三件首饰为 APC 专属标准装备。
3. 保持 AIC 的 `[additional character status]`、`[character status rate]`、`[attack damage rate]`、AI、技能和快捷道具不变。
4. 保持地图正常生成链，不为调试长期保留强制换人。
5. 实机观察玩家打 APC、APC 打玩家、整体三速，以及被移除装备效果是否造成明显战斗退化。

若伤害或速度不合适，下一轮只调整一个层级：优先 APC 专属装备，其次 AIC 基础倍率，最后才考虑技能或 AI。不要同时改多个系统后凭手感反推原因。

## 阶段五：扩展到新副本

- 先形成按武器类型、护甲类型和公共首饰拆分的 APC 专属装备池，再创建大量新 APC。
- 每个新 APC 仍需做原装备或模板效果审计，不能只按职业名套装。
- 新路线先用一个代表 APC 验证数值，再逐个加入；不要一次生成整条路线后统一猜测平衡。
- 多副本共享同一 APC 装备池时，装备修改的影响面必须写入 manifest。

## 输出与验收

- 源 PVF 未覆盖，输出路径显式。
- 新 ID、源模板 ID 和目标 APC ID均通过正确 registry 解析。
- 套装成员全部指向 APC 专属 ID。
- unresolved 值和保留槽位未被静默删除。
- 自动 readback 与独立严格 readback 均通过。
- 最终状态分为静态 PASS 和实机 PASS；只有目标版本的实机反馈才能说明伤害与速度体验合适。
