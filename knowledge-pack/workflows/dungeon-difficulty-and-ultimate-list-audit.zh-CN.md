# 副本难度系数与地狱名单核查流程

状态：默认可用

## 目标

分层核查副本难度 / revision `.tbl` 与地狱副本名单，输出可审阅差异和最小修改计划。两条线不能合并解释。

## 难度系数线

1. 从 dungeon ID 经 `dungeon/dungeon.lst` 解析 `.dgn`。
2. 读取目标实际存在的 `[monsterapc diff table]` 或 `[revision table]`；有显式路径时读取对应 `.tbl`，不得跨表族猜路径。
3. 没有显式路径时，只报告可能存在全局回退，不主动套用某个全局表。
4. 对 `.tbl` 记录完整块名、`type`、等级/难度段、行列数、数值精度和未识别部分。
5. 比较版本或副本时按同一块、同一行列位置对齐；结构不同标记 shape-divergent。
6. 只为已通过目标同表族最近邻或单变量实机 A/B 确认列义的单元格形成修改计划，不重建或截断整表。已验收样本中的 revision 前三项只能作为攻击、防御、生命候选线索，不能直接推广到另一表族。

## 地狱名单线

1. 读取 `etc/ultimatedungeonlist.etc [apply ultimate]`。
2. 按原始顺序逐项通过 `dungeon/dungeon.lst` 解析。
3. 输出顺序号、dungeon ID、路径、重复次数和解析状态。
4. 重复项保留为 duplicate；无法解析项保留为 unresolved。
5. 新增/删除计划只处理名单本身，不声称同步了难度倍率、掉落、任务、门票或服务端条件。

## 写出

1. 从目标 raw no-simplified 文本构建最小替换。
2. `.tbl` 修改前额外核对行列数和数值总数没有变化，除非任务明确要求结构变更。
3. 名单修改保持未授权的顺序与重复项。
4. 走同源同 change-set dry-run、approval code、显式输出、备份和读回。

## 实机验收

可把多个副本合并为一次高收益批次：检查普通/冒险/王者/地狱等可用档位、怪物强度变化、组队缩放、名单入口、进图与结算。名单与倍率分别记录结果；一个通过不能替另一个通过。
