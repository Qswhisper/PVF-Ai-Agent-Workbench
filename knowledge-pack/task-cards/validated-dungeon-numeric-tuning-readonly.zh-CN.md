# 已验收副本数值微调任务卡

状态：默认可用

用途：目标副本的入口、地图、刷怪、结算和客户端表现已经实机通过，后续只需要调整强度、次数、门票、奖励或掉率时，保护现有结构并选择一个最小数值入口。本任务卡不把任何副本预设为“后期”“终局”或固定内容组合。

## 版本与证据边界

1. 对照包、目标包和实机记录是三种证据：对照包说明原有结构，目标包说明当前静态内容，实机记录才说明运行结果。
2. 跨版本比较先记录双方完整 SHA256。显示名称、目录名、“官方版”或“成品版”称呼都不能代替版本身份。
3. 即使 registry ID 和 PVF 路径相同，显示名称、楼层、地图、出场对象和玩法定位也可能已改变；每次仍从目标 PVF 重新做名称搜索、registry 解析和目标文件读回。
4. 文档只保存可重复的选择方法，不保存某个成品的楼层表、地图 ID、APC ID、阵容清单或当前数值。

## 选择一个数值层

| 反馈 | 首选审计入口 | 边界 |
| --- | --- | --- |
| 入场次数、复活币、门票 | 当前 `.dgn` 的完整对应字段；物品 ID 通过 `stackable.lst` 解析 | 不顺手改变入口、地图或副本类型 |
| 通关奖励不合适 | 分开核对 `.dgn` 奖励、结算翻牌、任务奖励和独立掉落 | 四者不是同一系统 |
| 整体敌我强度不合适 | 先清点当前 `.dgn` 的 `[designate dungeon difficulty]`、`[basis level]`、内联 bonus，以及显式引用的 difficulty / revision table；一次只选其中一个 | 档位、基准等级、内联 bonus 和表格不是同一层；不把另一张表的列义套过来 |
| 单个怪物或 APC 异常 | 解析对应 registry，读取其 `.mob` / `.aic` 并审计复用范围 | 个人文件也可能被其他副本复用 |
| 某房间、波次或楼层异常 | 先判断是个体数值还是结构问题 | 地图、波次、楼层和出生链变化不属于纯数值微调 |
| AI、首发、召唤或清层异常 | 转入行为与依赖审计 | 不用提高攻防血掩盖行为错误 |
| 起始房间/第一阶段与后续阶段不一致 | 转入复杂副本机制壳审计，分别核对个体、地图和全局表 | 不从第一阶段单样本外推整张表已生效或失效 |

## 执行

1. 记录反馈条件：副本、难度、房间或阶段、职业装备、人数、耗时、受击压力和死亡原因。
2. 对自然语言副本名先走名称搜索，再按返回的 registry 身份读取 `.dgn`；不要从历史文档反推 ID 或路径。
3. 对照可用的基线，只把差异分为“原有结构”“目标改造”“仅有实机观察”三类。不能确认归属的结论保持未知。
4. 只选择一个主要杠杆。表格路线先确认实际标签、表族、`type`、目标等级/难度行和列义；写入前从目标 PVF raw 读回完整标签和精确旧值，禁止替换裸数字。
5. 预演（检查方案；中文改动会用临时文件验证并立即清理），确认精确命中、影响路径、结构冻结项和读回计划。
6. 经授权后生成独立的修改版 PVF，不覆盖源。生成后重新检查目标字段、引用闭合和未改结构。
7. 受控部署后做旧版/新版 A/B。结果未归因前，不叠加第二个主要杠杆。

## 停止条件

- 名称、registry、路径或文件结构与预期不一致。
- 需要修改地图、波次、楼层、出生对象、AI、registry、入口、中文等文字或客户端资源。
- 表的行列含义只能靠猜测，或同一反馈需要同时改变多个主要系统。
- 预演、临时往返、生成后重新检查或实机回归任一环节失败。
