# Client Assets / ImagePacks2 / NPK / UI / IMG 只读审计

状态：需验证

## 什么时候读

- 出现红叉、黑图、UI 缺图、地图贴图缺失、动画缺帧或 NPK/IMG 资源疑问。
- 需要区分“Script.pvf 写了资源引用”和“客户端 ImagePacks2 真的有资源”。
- 副本、怪物、宠物、装备、技能、活动 UI 等链路已经闭合，但仍怀疑客户端资源缺失。

## 默认动作

1. 先确认问题是资源侧，不把它误判成 PVF registry 缺失。
2. 查 `dictionaries/client-assets-imagepacks-ui-fields.zh-CN.md` 确认 `.ui/.ani/.act/.ptl/.til/.lay/.img/.npk` 的层级。
4. 若只看到 Script.pvf 引用，不写“客户端资源完整”。
5. 若 ImagePacks2 静态命中，只写“索引命中”，不写“实机显示正常”。
6. 若 ImagePacks2 静态未命中，写成客户端资源风险；需要实机或专门资源包验证。
7. 若目标是光环、时装或角色外观动画，区分图标 IMG、外观 ANI 内部 IMG、NPK 容器来源和目标客户端加载结果；任一静态命中都不能替代实机视觉。
8. 自制整合 NPK 工具可读、条目数正确或无解析异常，只能作为打包质量线索；不能单独证明目标客户端会按预期加载并显示。
9. 对目标原生的立绘/过场开关型字段，第一轮优先保留字段结构、只改变既有值；“删除整个字段”作为独立高风险变体。一个历史目标负例中，删除 `etc/ultimateskillcutscene.etc` 的 `[ONAIR ONLY]` 导致多职业进图卡加载，保留字段并把开关值改为关闭后进图与立绘恢复。这里只保留实验顺序，不外推全版本语义；验收至少同时覆盖多职业代表的进图加载与目标演出显示。


- 当前 ImagePacks2 只读索引观察到 NPK 1612 个、NPK 内 IMG 条目 80941 个、异常 NPK 容器 0 个。


## 不要写成

- 不写“实机一定无红叉”。
- 不写“UI 一定正常显示”。
- 不写“动画帧号一定有效”。
- 不写“NPK 加载顺序一定正确”。
- 不写“自制整合 NPK 与源客户端原始 NPK 在目标客户端中等价”。
- 不写“服务端放行”。
- 不写“只要 Script.pvf 有引用，客户端资源就完整”。

## 下一步怎么测

1. 对具体缺图或红叉，先定位触发 PVF 文件和 `.img` 候选路径。
2. 在目标客户端 ImagePacks2 中查 NPK 索引是否命中。
3. 若静态未命中，补齐或替换资源前必须另行授权客户端修改。
4. 若要验证新整合 NPK，先生成独立包，与原共享 NPK 共存测试。
5. 只有隔离 A/B 才临时禁用共享源 NPK，且必须准备恢复方案。
