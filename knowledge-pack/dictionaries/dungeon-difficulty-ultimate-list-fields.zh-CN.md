# 副本难度系数与地狱名单词典

状态：默认可用

## 为什么必须分开

副本难度数值表和“允许选择地狱难度的副本名单”是两个系统：

- 难度表决定怪物/APC 难度参数候选。
- 地狱名单只表示某些 dungeon ID 被列入静态允许集合。

名单命中不能证明某个倍率生效，难度表存在也不能证明地狱难度入口可选。

## `.dgn [monsterapc diff table]`

状态：默认可用

含义：指定副本使用的 monster/APC 难度 `.tbl` 路径。

边界：没有独立表时可能使用全局表或其他回退机制，但回退必须由目标同版本样本或运行结果证明，不能凭文件名补写。

## `.dgn [revision table]`

状态：需验证

含义：塔式或其他特殊副本可显式引用一份 `[Revision Table]` 属性修正表。它与 `[monsterapc diff table]` 是不同表族；目标实际出现哪个标签，就沿哪个标签读取，不互相替代。

边界：同一路径 token、同名表或同一 dungeon ID 都不能证明跨版本行列语义一致。没有显式引用时不得按历史路径猜表。

## `.dgn [designate dungeon difficulty]`

状态：需验证

含义：部分普通副本用数字选择一个静态难度档位候选。

边界：数字到显示难度名称、AI 行为和最终倍率的映射必须由目标同版本样本或实机确认；不能把它与 `[basis level]` 或难度表单元格当作同一个杠杆。

## `.dgn [basis level]`

状态：默认可用

含义：副本的静态基准等级线索，可能参与怪物等级、数值或结算选行。

边界：它不是单纯的“整体难度倍率”，也不等同最低/推荐等级。调整前先确认目标副本是否实际受它影响，并单独做 A/B。

## `[Revision Table]`

状态：需验证

已验收样本观察到按 `[type]` 分开的 `character`、`apc`、`monster` 块。一个已完成实机 A/B 的塔式表族中，所选等级行的前三项分别用于总体攻击、总体防御和最大生命修正；这只是一条可复核的表族线索，不是所有 revision table 的全局列定义。

处理规则：

1. 先确认 `.dgn` 的显式引用、目标表完整 SHA/形状、`type` 和目标等级行。
2. 只有目标表同族邻居或当前目标的单变量实机 A/B 支持时，才把前三项按攻击、防御、生命解释。
3. 其余列保持未知；不因数值排列相似就套用列义。
4. `character` 与 `apc` / `monster` 分开汇报；改变玩家侧与敌方侧不是同一个杠杆。

## 难度 `.tbl`

状态：需验证

已观察形状包含大规模浮点矩阵、等级段、难度段和属性列，并可能出现 `[dungeon party balance]`、`[easy]` 等块。这里描述的是 difficulty table 家族，不自动覆盖上面的 `[Revision Table]`。

处理规则：

1. 先区分全局表与 `.dgn` 指向的副本专用表。
2. 保留目标文件所有块、完整行列数、精度、顺序和未展示部分。
3. 只修改已经通过目标邻居确认列义的单元格或行。
4. 不按某个工具显示出的固定数字数量截断或重建整表。
5. 静态数值变化不等于实机难度、血量、攻击、经验或组队缩放一定变化。

## `etc/ultimatedungeonlist.etc`

### `[apply ultimate]`

状态：默认可用

含义：地狱难度应用名单。每个 dungeon ID 按 `dungeon/dungeon.lst` 解析。

处理规则：

- 保留原始顺序。
- 保留重复项并在报告中单独标记；未获授权不得静默去重。
- 报告无法解析的 ID，但不要删除。
- 名单存在只证明静态配置，不证明地狱难度运行、掉落、UI、门票或服务端放行。

## 计划状态

- `resolved`：ID 或路径通过目标 registry 闭合。
- `duplicate`：名单中重复出现；保留并提示。
- `unresolved`：ID、路径或 `.tbl` 无法闭合。
- `fallback-candidate`：可能回退全局表，但尚无目标证据。
- `shape-divergent`：目标 `.tbl` 行列或块结构与参考计划不同，禁止套表。
